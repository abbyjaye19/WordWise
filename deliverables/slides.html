WordWise

An AI reading studio that helps students with dyslexia and other reading difficulties understand what they read, using their own course materials.

Problem

Reading support is scarce, fragmented, and focused on decoding

≈5–6%of U.S. students are formally identified with a learning disability in reading and language processing (IDA: 6–7% classified LD × ~85% reading-based)
15–20%of the population show some symptoms of dyslexia; most never qualify for special-education services (IDA)
Costly“Specialized instruction is expensive,” and many families cannot find qualified providers (IDA)

How students cope today

  • Specialized tutoring: most effective option, but costly and capacity-constrained
  • IEP / 504 accommodations: extended time and audio, applied mainly at school rather than to nightly reading
  • Point tools: text-to-speech, dictionaries, general chatbots; separate apps not calibrated to reading level

Cost to the student

More time per assignment and weaker comprehension; difficulties compound as academic demands increase (IDA).

Target users: students aged roughly 5–30 reading textbooks, assignments, lecture slides, and books for pleasure; secondary users are parents and tutors.

Architecture

Four focused agents behind one guard layer

Design principles

  • AI only where it adds value. Display, read-aloud, highlighting, and folders run without model calls ($0).
  • Single-call, tool-less agents. One click = one call; no agent loops, so cost and failure modes are bounded.
  • One guard layer for every call: budget cap, input caps, <reading> delimiting, model check, token and cost logging.
  • One shared, cached prompt prefix (safety rules + reader-level guide) for all agents.
  • Student data stays local: accounts and saved work never reach the model.

Why gpt-6-luna

  • Course-mandated model, accessed via the course Portkey gateway (Azure OpenAI)
  • Short, well-specified language tasks suit a small, inexpensive model
  • JSON-schema outputs for three agents: reliable rendering and a narrower injection surface

Measured design choices

  • Reasoning effort low: “medium” raised word-lookup cost 93% and latency 65%
  • Four reader levels (5–8, 9–12, 13–17, 18+), chosen by the student and applied through the shared guide
  • Every reply is verified as gpt-6-luna; any other model stops the request

Cost-cutting experiment

  • Finding: 0 cached tokens on every call; prompts (~650 tokens) were below the provider's 1,024-token caching minimum
  • Change: one shared reader-level guide prepended to all agents (~1,600-token static prefix)
  • Result: input tokens doubled, but 89% are billed at the cached rate (10× cheaper): −29% per session
  • Trade-off check: the same 6 words at ages 5–8 and 18+, with vs. without the guide, showed no quality loss (average sentence 9.3 → 8.9 words)
  • Also: gateway replays logged at $0; the daily cap must scale with users (~$5.50/day at 10,000)

User evaluation design

  • Within-subject pilot (1–3 users: student, parent, tutor): one passage without WordWise, one with; passage order counterbalanced (grade 5.9 vs. 6.9 texts)
  • Measures: reading time, comprehension (3 questions scored 0 / ½ / 1), 6-item survey, observed tool use, verbatim quotes

Status: protocol and materials complete; pilot sessions in progress. Results are added to the report when collected.

Limits and next steps

What would make this production-ready

Current limits

  • Level control is imperfect: 2 of 6 answers for ages 5–8 met the <10-word sentence target
  • No OCR, so scanned PDFs can't be read
  • Read-aloud quality depends on browser voices
  • Local deployment; spending cap is global, not per student
  • Red-team checks are rule-based plus human review; small pilot sample

Next steps

  • Larger user study measuring time per assignment and quiz accuracy
  • Self-check pass to enforce reader-level targets
  • OCR for scanned pages and phone photos of books
  • Hosted version: managed database, per-student limits, privacy review (COPPA for under-13s)
  • Teacher view for shared assignments, which benefit from the replay cache
